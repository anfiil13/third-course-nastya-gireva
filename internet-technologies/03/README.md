1. Какой endpoint используется
`https://jsonplaceholder.typicode.com/users` 

2. Какой HTTP-метод отправляется
`GET` — только чтение данных.

3. Где в программе хранится состояние
В объекте `state` в начале `app.js`:
- `users` — массив от сервера,
- `isLoading` — идёт ли запрос,
- `error` — текст ошибки или `null`,
- `filter` — строка поиска.

Сетевой код меняет `state`, а `render()` только читает его и обновляет DOM.

4. Какие состояния интерфейса предусмотрены
- загрузка — `isLoading === true` → «Загрузка...»;
- ошибка — `error !== null` → «Ошибка: ...»;
- данных ещё нет — `users.length === 0` → подсказка;
- успех — список карточек.
Плюс отдельно: «Ничего не найдено», если фильтр не дал совпадений.

5. Как обрабатывается ошибка
- Проверка `response.ok` — `fetch` не бросает ошибку при 404/500.
- Обёртка в `try/catch` — ловит HTTP-ошибки и сетевые сбои.
- Текст ошибки → в `state.error` и в консоль.
- Блок `finally` всегда сбрасывает `isLoading = false`, поэтому интерфейс не зависает в «Загрузка...».

6. Какие поля участвуют в фильтрации
Три поля: `name`, `username`, `email`. Регистр не учитывается, поиск по подстроке. Исходный массив не мутируется — `getFilteredUsers` возвращает новый.

7. Что видно в Network при успешном запросе и при ошибке

Успех:
- строка `users`, метод `GET`, статус `200`;
- Headers → `Content-Type: application/json`;
- Response / Preview → JSON-массив;
- Time → длительность запроса.

Ошибка (неверный URL):
- статус `404`;
- Response → пустой ответ или страница ошибки;
- в консоли → `Ошибка HTTP: 404 Not Found`;
- в интерфейсе → «Ошибка: ...», кнопка «Обновить» неактивна, зависания нет.
