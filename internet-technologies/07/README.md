# ЛР7. Браузерный интерфейс для собственного API

## Установка и запуск

```bash
npm install
node server.js
```

Открыть: `http://localhost:3000` (не через `file://`).

## Структура проекта

```text
07/
  server.js          — Express: API /api/books + раздача папки public
  package.json
  package-lock.json  — появляется после npm install
  .gitignore         — node_modules/, data.db
  public/
    index.html       — разметка: форма, фильтры, список, сообщения
    style.css        — оформление
    app.js           — fetch, состояние, render(), обработчики
  README.md
```

## Схема обмена

```text
пользователь нажимает кнопку
        ↓
app.js: обработчик события
        ↓
fetch('/api/books', { method, headers, body: JSON.stringify(...) })
        ↓
Express-маршрут (server.js) → валидация
        ↓
SQL с параметрами "?" → SQLite (data.db)
        ↓
JSON-ответ + HTTP-код
        ↓
request(): проверка response.ok, 204 без тела
        ↓
refreshBooks() → books[] → render() → DOM
```

Главное правило: **база — постоянный источник данных, массив `books` — текущая копия для интерфейса**. После любого POST/PATCH/DELETE страница заново запрашивает список, чтобы показывать то, что реально хранится на сервере.

## Используемые маршруты API

| Метод | URL | Где используется в интерфейсе | Успех |
|---|---|---|---:|
| GET | /api/books | загрузка списка, кнопка «Обновить» | 200 |
| GET | /api/books?q=...&available=... | поиск и фильтр над списком | 200 |
| POST | /api/books | форма «Добавить книгу» | 201 |
| PATCH | /api/books/:id | галочка «в наличии», кнопка «Изменить» → «Сохранить» | 200 |
| DELETE | /api/books/:id | кнопка «Удалить» (с подтверждением) | 204 |

## Что может делать пользователь

- видеть список книг сразу после открытия страницы («Список пуст», если книг нет);
- добавить книгу (название обязательно, автор и год — по желанию);
- отметить/снять «в наличии» — PATCH только поля `available`;
- изменить название и автора — PATCH двух полей;
- удалить книгу — после `confirm()`;
- искать по названию и фильтровать по наличию (фильтры выполняются на сервере через `WHERE`);
- перезагрузить список кнопкой «Обновить».

Всё работает без перезагрузки страницы (`event.preventDefault()` в обработчике формы).

## Состояния и ошибки

Состояние страницы: `books` (данные), `loading`, `loadError`, `editingId`. Интерфейс обновляется только через `render()`.

| Ситуация | Что видит пользователь |
|---|---|
| идёт запрос | «Загрузка...», кнопка «Обновить» неактивна |
| данные пришли | «Загружено книг: N» и список |
| записей нет | «Список пуст» |
| сервер выключен | «Ошибка загрузки: Сервер недоступен...» (не бесконечная загрузка) |
| 400 | красное сообщение с текстом ошибки от сервера |
| 404 | красное сообщение «HTTP 404: Book not found» |
| успешная операция | зелёное сообщение, исчезает через 3 с |
| DELETE → 204 | `request()` возвращает `null`, не вызывая `response.json()` |

Почему нельзя полагаться только на `try/catch`: `fetch()` не бросает исключение на 400/404 — сервер ведь ответил. Поэтому в `request()` явно проверяется `response.ok`. Исключение у `fetch()` бывает, только если ответа нет совсем (сервер выключен) — этот случай обработан отдельно.

## Проверка ввода

| Ввод | Результат |
|---|---|
| пустое название | «Введите название книги», запрос не отправляется |
| название из пробелов | то же самое (`trim()`) |
| «Война и мир», Лев Толстой, 1869 | `POST 201`, книга появилась в списке |
| год 3000 (клиент пропускает, сервер — нет) | `POST 400`: «HTTP 400: year must be an integer from 1 to 2027 or null» |

Клиентская проверка только делает интерфейс удобнее. Серверная валидация из ЛР6 осталась и продолжает работать — её нельзя обойти, отправив запрос напрямую.

## Проверка 400 / 404

- `POST /api/books` с годом 3000 → **400**, сообщение показано на странице;
- `DELETE /api/books/999` → **404** `{"error":"Book not found"}`;
- если удалить книгу, которую в другой вкладке уже удалили, интерфейс покажет «HTTP 404: Book not found» и обновит список.

Фрагмент вкладки Network при проверке:

```text
GET    /api/books                200
POST   /api/books                201
POST   /api/books                400
PATCH  /api/books/2              200
GET    /api/books?available=false 200
DELETE /api/books/3              204
DELETE /api/books/999            404
```

## Сохранение после перезапуска

1. Добавили через страницу «Война и мир» и «Мастер и Маргарита».
2. Остановили сервер (Ctrl+C), нажали «Обновить» → «Сервер недоступен».
3. Запустили `node server.js` снова, открыли страницу.
4. Обе книги на месте — данные лежат в `data.db`.

## Почему textContent, а не innerHTML

Название книги приходит от пользователя. Если вставить его через `innerHTML`, браузер разберёт его как HTML: `<b>Проверка</b>` станет жирным текстом, а `<img src=x onerror=...>` выполнит чужой JavaScript (XSS). `textContent` всегда вставляет строку как обычный текст.

Проверка: книга с названием `<b>Проверка</b>` отображается буквально, с угловыми скобками.
