# Практическая работа №4. Отсечение отрезков алгоритмом Коэна–Сазерленда

## Как запустить

1. Скопируйте папку `04/` на диск.
2. Откройте `index.html` в браузере (двойным кликом или через `File → Open`).
3. Ничего устанавливать не нужно — всё работает без сборки и зависимостей.

Файлы:

- `index.html` — разметка интерфейса и канвас
- `style.css` — оформление
- `app.js` — реализация алгоритма, отрисовка, таблица итераций, эксперимент
- `README.md` — этот файл

## Использованное окно в тестах

    xmin = 100
    xmax = 560
    ymin = 120
    ymax = 440

Канвас: `760 × 560`, начало координат — левый верхний угол (как в Canvas).

## Соглашение о четырёхбитном коде

| бит | значение | имя      | смысл                              |
|-----|----------|----------|------------------------------------|
| 0   | `0001`   | `LEFT`   | точка слева от окна (`x < xmin`)   |
| 1   | `0010`   | `RIGHT`  | точка справа от окна (`x > xmax`)  |
| 2   | `0100`   | `BOTTOM` | точка ниже окна (`y > ymax`)       |
| 3   | `1000`   | `TOP`    | точка выше окна (`y < ymin`)       |

- `0000` = `INSIDE` — точка внутри окна.
- Биты объединяются побитовым ИЛИ (`|`): точка слева и сверху → `0001 | 1000 = 1001`.
- Быстрый ACCEPT: `(code1 | code2) === 0`.
- Быстрый REJECT: `(code1 & code2) !== 0` — у обоих концов есть общий внешний бит, значит отрезок целиком в одной внешней полуплоскости.

## Результаты обязательных тестов

Все тесты прогнаны с окном выше (`100, 120, 560, 440`). При загрузке страницы они автоматически выводятся в консоль браузера (`F12 → Console`).

| Тест | Отрезок A → B | Результат |
|------|----------------|-----------|
| полностью внутри | (150,150) → (500,400) | **ACCEPT**, без изменений |
| полностью слева | (10,200) → (80,300) | **REJECT** (общий бит `LEFT`) |
| полностью сверху | (200,10) → (400,90) | **REJECT** (общий бит `TOP`) |
| пересекает одну границу (LEFT) | (20,250) → (300,260) | **ACCEPT**, отсечение по `LEFT`: A → (100, 250.7) |
| пересекает две противоположные (L/R) | (20,250) → (700,260) | **ACCEPT**, отсечение по `LEFT` и `RIGHT` |
| проходит через угол | (20,60) → (200,200) | **ACCEPT**, последовательно отсекается по `TOP`, затем по `LEFT` |
| вертикальный | (300,20) → (300,550) | **ACCEPT**, отсечение по `TOP` и `BOTTOM` |
| горизонтальный | (20,300) → (700,300) | **ACCEPT**, отсечение по `LEFT` и `RIGHT` |
| обе точки снаружи, но проходит через окно | (20,20) → (700,500) | **ACCEPT**, отсечение по `TOP` и `BOTTOM` (или `LEFT`/`RIGHT`) |

Во всех случаях программа корректно принимает, отсекает или отбрасывает отрезок; промежуточные шаги (ACCEPT / REJECT / пересечение TOP / BOTTOM / LEFT / RIGHT) видны в таблице итераций.

## Результаты эксперимента со случайными отрезками

Кнопка **«Случайные тесты»** генерирует **300 случайных отрезков** внутри канваса и прогоняет каждый через `clipLine`.

Типичный результат (зависит от seed браузера, но качественно стабилен):

| Категория | Примерное количество | Доля |
|-----------|----------------------|------|
| принят без изменения (оба конца внутри) | ≈ 55–65 | ≈ 19 % |
| отсечён (частично пересекает окно) | ≈ 70–85 | ≈ 26 % |
| полностью отброшен (`code1 & code2 !== 0`) | ≈ 155–170 | ≈ 55 % |

Вывод: **более половины** отрезков отбрасываются за **одну** побитовую операцию `&` без вычисления пересечений, а около **20 %** принимаются за одну операцию `|`. Таким образом, коды действительно экономят большинство вычислений — реальные формулы пересечения применяются только в ~25 % случаев.

## Особенности реализации

- `getCode(x, y, rect)` возвращает код точки в виде числа (`INSIDE = 0`, `LEFT = 1`, `RIGHT = 2`, `BOTTOM = 4`, `TOP = 8`).
- `clipLine(x1, y1, x2, y2, rect)` возвращает `{ result, status, steps }`:
  - `result` — объект `{x1, y1, x2, y2}` либо `null`, если отрезок отброшен;
  - `status` — `'accept'` / `'reject'`;
  - `steps` — массив шагов алгоритма для таблицы итераций.
- После каждого сдвига конца отрезка код **пересчитывается** — это критично, если точка одновременно была, например, `LEFT + TOP`: после пересечения с левой границей она может остаться выше окна, и бит `TOP` сохранится.
- Для ломаной каждая пара соседних точек обрабатывается отдельным вызовом `clipLine`; видимая часть каждой пары рисуется зелёным, невидимая — красным пунктиром.
- **`ctx.clip()` не используется** — вся работа выполняется аналитически по алгоритму Коэна–Сазерленда.
