## 1. Чем идея Брезенхема отличается от ЦДА?

Алгоритм ЦДА работает с непрерывной математической моделью: на каждом шаге
к текущим координатам прибавляются вещественные приращения xStep и yStep,
после чего результат округляется до ближайшего пикселя. ЦДА фактически
«идёт вдоль» идеальной линии и постоянно округляет её координаты.
Алгоритм Брезенхема не вычисляет реальные координаты линии, а поддерживает целочисленную величину ошибки
error, которая показывает, насколько текущий выбранный пиксель отклонился
от идеальной линии. По величине этой ошибки алгоритм решает, нужно ли на
очередном шаге сделать дополнительный сдвиг по второй координате. В
результате Брезенхем обходится только целочисленными операциями сложения,
вычитания и сравнения — без деления и округления.

## 2. Для чего используется переменная error?
Переменная error хранит накопленное отклонение текущего пикселя от
идеальной математической линии. Именно она заменяет собой честное
вычисление расстояния до линии на каждом шаге.

## 3. Зачем нужны sx и sy?
sx и sy задают направления движения по осям X и Y соответственно:
    const sx = x1 < x2 ? 1 : -1;
    const sy = y1 < y2 ? 1 : -1;

## 4. Почему две проверки изменения координат нельзя бездумно заменить на if ... else?
Потому что на некоторых шагах алгоритма изменяются обе координаты
одновременно — это диагональный шаг. Проверки устроены так:

    if (error2 > -dy) { error -= dy; x += sx; }
    if (error2 < dx)  { error += dx; y += sy; }

Если вторую проверку сделать через else if, то случай, когда нужно
сделать сразу оба шага, будет обработан неправильно — второй сдвиг
просто не выполнится. В результате линия сломается: появятся
пропущенные или неверные пиксели.

## 5. На каких входных данных вы обязательно проверяли программу?
Программа обязательно проверялась на следующих случаях:
- Горизонтальный отрезок: (2, 5) -> (20, 5)
- Вертикальный отрезок: (7, 2) -> (7, 20)
- Пологая линия, dy < dx: (2, 2) -> (8, 5)
- Крутая линия, dy > dx: (3, 2) -> (7, 25)
- Отрезок, построенный справа налево: (20, 8) -> (2, 3)
- Отрезок, построенный снизу вверх: (5, 20) -> (15, 2)
- Одна точка: (10, 10) -> (10, 10)
Если хотя бы один из этих случаев не отрабатывает корректно,
реализация считается неполной.

## 6. Совпали ли наборы пикселей ЦДА и Брезенхема во всех ваших примерах?
Нет, совпали не во всех примерах.
Для горизонтальных, вертикальных и строго диагональных отрезков наборы
пикселей обычно совпадают, потому что там нет неоднозначности в выборе
следующего пикселя.
Для наклонных отрезков, особенно когда накопленная ошибка оказывается
на границе или наклон близок к 0,5, алгоритмы могут выбрать разные
пиксели на отдельных шагах. Причина в том, что ЦДА округляет вычисленную
вещественную координату, а Брезенхем принимает решение по накопленной
целочисленной ошибке. В пограничных ситуациях эти два правила дают
разные результаты.
