# ЛР6. Отсечение многоугольника: алгоритм Сазерленда–Ходжмана

## Способ задания многоугольника

1. **Готовые тесты** — выпадающий список «Тест» (массивы вершин в `tests.js`).
2. **Мышью** — кнопка «Задать мышью», щелчки по холсту добавляют вершины, «Завершить» или двойной щелчок замыкают контур (минимум 3 вершины).

## Параметры окна

По умолчанию: `xmin = 150`, `xmax = 450`, `ymin = 100`, `ymax = 330`. Значения можно поменять в панели «Окно отсечения». Перед применением проверяется, что все поля — числа, `xmin < xmax` и `ymin < ymax`; иначе выводится ошибка, а окно не меняется.

## Таблица четырёх переходов

Для ребра S → P (S — предыдущая вершина, P — текущая) относительно **одной** границы:

| S | P | Что записать в результат |
|---|---|---|
| inside | inside | P |
| inside | outside | точку пересечения |
| outside | inside | точку пересечения, затем P |
| outside | outside | ничего |

Условия inside:

```text
LEFT:   x >= xmin
RIGHT:  x <= xmax
TOP:    y >= ymin
BOTTOM: y <= ymax
```

Точка, лежащая ровно на границе, считается inside (нестрогое неравенство).

Обход начинается с `S = последняя вершина`, чтобы первым обработалось замыкающее ребро «последняя → первая».

## Формулы пересечения

Ребро в параметрическом виде: `x = x1 + t(x2 − x1)`, `y = y1 + t(y2 − y1)`.

Вертикальная граница `x = xB`:

```text
t = (xB − x1) / (x2 − x1)
y = y1 + t · (y2 − y1)
```

Горизонтальная граница `y = yB`:

```text
t = (yB − y1) / (y2 − y1)
x = x1 + t · (x2 − x1)
```

Деления на ноль не бывает: функция пересечения вызывается только когда S и P по разные стороны границы, значит `x2 ≠ x1` (или `y2 ≠ y1`).

## Порядок обработки

```text
исходный → LEFT → RIGHT → TOP → BOTTOM
```

Выход каждой границы — вход следующей. Если после какого-то этапа список вершин пуст, следующие границы не обрабатываются.

## Промежуточные списки вершин (тест 5 — пересекает все четыре границы)

Исходный ромб: `(300, 40) (520, 215) (300, 390) (80, 215)`.

| Этап | Число вершин | Координаты |
|---|---:|---|
| исходный | 4 | (300, 40) (520, 215) (300, 390) (80, 215) |
| LEFT | 5 | (150, 159.32) (300, 40) (520, 215) (300, 390) (150, 270.68) |
| RIGHT | 6 | (150, 159.32) (300, 40) (450, 159.32) (450, 270.68) (300, 390) (150, 270.68) |
| TOP | 7 | (150, 159.32) (224.57, 100) (375.43, 100) (450, 159.32) (450, 270.68) (300, 390) (150, 270.68) |
| BOTTOM | 8 | (150, 159.32) (224.57, 100) (375.43, 100) (450, 159.32) (450, 270.68) (375.43, 330) (224.57, 330) (150, 270.68) |

Здесь хорошо видно, что при отсечении вершин может становиться **больше**: каждая граница срезает один угол ромба, а вместо одной вершины появляются две точки пересечения. Итог — восьмиугольник.

## Ручной расчёт (тест 3, граница LEFT)

Многоугольник: `(100, 180) (250, 150) (260, 260) (90, 250)`, граница `x = xmin = 150`.

Берём ребро **S = (100, 180) → P = (250, 150)**.

- S: `100 >= 150` — ложь → **outside**
- P: `250 >= 150` — истина → **inside**
- Случай **outside → inside**: добавляем пересечение, затем P.

Пересечение с вертикальной границей:

```text
t = (150 − 100) / (250 − 100) = 50 / 150 = 1/3
y = 180 + 1/3 · (150 − 180) = 180 − 10 = 170
```

Точка пересечения: **X = (150, 170)**.

В выходной массив добавлено: `(150, 170)`, затем `(250, 150)`.

Весь этап LEFT для этого теста:

| S | P | Переход | Добавлено |
|---|---|---|---|
| (90, 250) | (100, 180) | outside → outside | ничего |
| (100, 180) | (250, 150) | outside → inside | (150, 170), (250, 150) |
| (250, 150) | (260, 260) | inside → inside | (260, 260) |
| (260, 260) | (90, 250) | inside → outside | (150, 253.53) |

Результат LEFT: `(150, 170) (250, 150) (260, 260) (150, 253.53)` — по-прежнему 4 вершины. Остальные границы этот многоугольник не меняют.
