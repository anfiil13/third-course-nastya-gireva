1. Растеризация — это процесс преобразования геометрического объекта (например, математического отрезка) в набор дискретных элементов растра — пикселей. Экран не может изобразить непрерывную линию, поэтому приходится выбирать, какие именно клетки сетки закрасить, чтобы они как можно лучше передавали форму объекта.

2. Число шагов в ЦДА берётся равным max(|dx|, |dy|), чтобы за один шаг ни одна из координат не изменялась больше чем на 1 пиксель. Если бы шагов было меньше, например |dx|, то при крутом наклоне (большой dy) по вертикали получались бы «дырки» — линия была бы разрывной. Максимум из модулей гарантирует связность: соседние пиксели всегда стоят рядом хотя бы по одной из осей.

3. Приращения xStep и yStep — вещественные числа. После каждого шага текущие координаты тоже вещественные, например (3.0, 2.5). Но пиксель существует только в целочисленных координатах — он не может занимать половину клетки. Поэтому вещественные координаты округляются до ближайшего целого: Math.round(2.5) = 3. Именно округление превращает непрерывную математическую траекторию в дискретный набор пикселей.

4. Что произойдёт, если начало и конец отрезка совпадут?
Тогда dx = 0 и dy = 0, значит steps = max(0, 0) = 0. Деление dx / steps и dy / steps привело бы к делению на ноль, поэтому этот случай обрабатывается отдельно: алгоритм просто ставит один пиксель в точке (x1, y1) и завершается. В коде это ветка if (steps === 0).

5. Недостатки ЦДА
Вещественная арифметика. Приращения и текущие координаты — дробные числа, операции с плавающей точкой медленнее целочисленных.

Деление на каждом отрезке. xStep = dx / steps и yStep = dy / steps — две операции деления, которые дороже сложения.

Округление на каждом шаге. Math.round() вызывается дважды за шаг, что добавляет вычислений.

Накопление погрешности. При многократном прибавлении дробного приращения x += xStep ошибка накапливается, и на длинных отрезках пиксели могут «уезжать» от идеальной линии.
